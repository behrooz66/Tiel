# LocalChat

A private, single-user chat app for local LLMs: a Blazor Web App (interactive server rendering, .NET 10) talking to a local Ollama server, with projects, conversations, messages and settings stored in SQLite.

## Source of truth

- `docs/phase-0-spec.md` is the full specification: schema, service interfaces, generation pipeline, UI, and the ordered task list (T0 to T13) with acceptance criteria. Read it before starting any work.
- `docs/decisions.md` records every choice made where the spec was silent. Read it too, and append to it.

## How to work

- At the start of a session, check `git log` to find the last completed task, then continue with the next one.
- Work through the tasks in order, one at a time. Finish a task's acceptance criteria before starting the next.
- One task per commit. Commit messages start with the task id, for example `T5: projects`.
- Before every commit, `dotnet build` and `dotnet test` must both pass.
- When the spec is silent or ambiguous, choose the simplest option that fits it, log it in `docs/decisions.md`, and continue.
- Stop and ask before changing the schema, the service interfaces or the generation events.
- At the end of each task, report what was built, what was tested, and any deviation from the spec.

## Architecture rules

- Components stay thin. All rules and validation live in `Services/`. `PromptBuilder` and `TokenEstimator` stay pure.
- Never inject `AppDbContext` into a component. Services use `IDbContextFactory<AppDbContext>`, one context per operation.
- Code against `IChatClient` (Microsoft.Extensions.AI); use `IOllamaApiClient` only for Ollama-specific calls.
- Replies are generated by `GenerationService` in a background task. Components only subscribe to its events, marshal them with `InvokeAsync`, and dispose their subscriptions.
- The `AppSettings` table is key-value (`Id`, `Key`, `Value`, `UpdatedAt`). Only `SettingsService` touches it; a new setting is a new entry in `SettingDefinitions`, never a new column.
- JavaScript interop only for: code highlighting, copy to clipboard, scroll handling, the composer's Enter key.

## Hard constraints

- Bind to `localhost` only. No authentication exists in phase 0.
- Send nothing anywhere except the configured Ollama endpoint. No telemetry, analytics or CDN-loaded assets; vendor front-end libraries into `wwwroot/lib`.
- Tests must never need a running Ollama; use fakes behind the client provider interface.
- Don't build ahead: no auth, tools, uploads, REST API or remote access, even as stubs.
- Verify library APIs against current documentation (Blazor in .NET 10, Microsoft.Extensions.AI, OllamaSharp, EF Core 10, Fluent UI Blazor, Markdig, bUnit) instead of guessing.

## Style

- C#: file-scoped namespaces, nullable enabled, records for DTOs, `async` all the way down with a `CancellationToken` on every I/O call, never `.Result` or `.Wait()`.
- Timestamps are UTC `DateTime` (not `DateTimeOffset`). IDs are `Guid.CreateVersion7()`.
